# scripts/ — code review

**Purpose:** operator entry points (bring-up, tear-down, demos, restore test) and their test harness. Everything is bash, written to run identically in Git Bash on Windows and in Linux CI.

| Path | What it is |
|---|---|
| `lib/` | Shared helpers sourced by every script (see `lib/code-review.md`) |
| `tests/` | Tests for the scripts themselves (see `tests/code-review.md`) |
| `up.sh` | **One command from an empty laptop to a running platform.** 1. Preflight: tools, Docker running and ≥ 9 GiB, `gh` authenticated. 2. `state-up.sh`. 3. `terraform apply` 10-cluster → 20-data (then the contract test) → 30-gitops. 4. Polls `platform_test.sh` until Argo CD has installed the platform (≤ 20 min). 5. `runner-up.sh`, skipped with `--no-runner`. It prints the URLs and the Argo CD password. Idempotent, so re-running is safe. |
| `down.sh` | `down.sh` runs `terraform destroy` 30 → 20 → 10 and keeps the state DB. `--purge` deletes the kind cluster, the state container and volume, and the local state files, but **keeps the deploy key**. Both stop and deregister the runner. |
| `bump-release.sh` | `bump-release.sh <stage> <chart-version> <sha256:digest>` **is the deployment.** It rewrites `gitops/releases/<stage>.yaml` and commits `release(<stage>): chart <v> image <short>`. It validates the stage (`dev`, `staging`, `prod-ring0`, `ring1`, `ring2`), a semver version and a `sha256:<64 hex>` digest. **It is race-safe:** if main moved, it does `pull --rebase` and retries the push up to 5 times. **It is idempotent:** re-promoting what a stage already runs makes no commit. It needs no yq, so it runs on plain CI runners. |
| `gate.sh` | `gate.sh <stage> <stack...>` is **the promotion gate**. It is read-only and runs on the self-hosted runner. Per stack: 1. the Argo CD app `stack-<s>` is Synced/Healthy at the stage's **chart version**; 2. Rollouts `api` and `worker` are Healthy, complete (stable == current), and running the stage's **image digest**; 3. after `GATE_SOAK` (180 s), Prometheus via the API-server service proxy shows a 5xx ratio < 0.5% and p95 < 0.4 s; 4. the oldest queued job is < 120 s. **Empty or NaN results count as "no traffic", which is a failure.** Checks 1–2 poll until `GATE_TIMEOUT` (900 s), so the gate can't hang. Output is `GATE PASS …` or `GATE FAIL <stage>/<stack>: <check>: <detail>`. `EXPECT_VERSION`/`EXPECT_DIGEST` let the pipeline assert the artifact it built. |
| `preflight-load.sh` | Run before a load test on the laptop. It pins dev, staging, acme and globex to 1 replica (KEDA `paused-replicas=1`). It then sums the memory requests of running pods and adds prod's projected growth to its KEDA maximums (API and worker). It **refuses to start if the projected peak exceeds 6.5 GiB**, so OOM kills can't masquerade as app errors. `--restore` unpins. Last run: 4.3 GiB now, 6.3 GiB projected peak, 346 MiB headroom. |
| `scaling-timeline.sh` | `scaling-timeline.sh <ns> <seconds>`: every 5 s, writes a CSV row with the API and worker desired/ready replicas, the queue depth (`LLEN jobs`) and the stack's edge request rate from Prometheus. It's the source of the scaling graphs in evidence 03. |
| `canary-timeline.sh` | `canary-timeline.sh <ns> <start> <end> [step]`: rebuilds a canary **after the fact** from Prometheus range queries. It writes one CSV row per step with stable vs canary req/s (the real traffic split), canary %, 5xx/s, edge p95, the HPA's desired replicas, and ready pods per api ReplicaSet. Written because a live recorder can stop early or miss events; Prometheus already recorded everything. It needs no state from the time of the run, only the retention window (default 10 days locally). |
| `runner-up.sh` | Fully scripted runner bring-up. It applies the `ci-gate` RBAC (view, Argo read, and the Prometheus proxy only), writes a token kubeconfig for the **internal** API endpoint (`zdp-control-plane:6443`), builds `zdp-runner:local`, fetches a registration token from the GitHub API, and starts the container on network `kind`. It then waits for the runner to come online and **proves read-only access**: it can read Applications, and a server-side dry-run delete must fail. |
| `deploy-key.sh` | Generates an ed25519 key into `.local/`. It (re)adds it as the write-enabled deploy key `gitops-release`, which the ruleset lets bypass, and stores the private half as the Actions secret `GITOPS_DEPLOY_KEY`. It is idempotent. **It must be run by the repo owner:** an AI agent isn't allowed to write repository secrets. |
| `state-up.sh` | Idempotently starts `zdp-tfstate` (`postgres:18.6-alpine`, `127.0.0.1:5433`, volume `zdp-tfstate`). On first run it generates a 32-hex-character password into `.local/tfstate.env` as `PG_CONN_STR` (chmod 600). It refuses to continue if the volume exists but the env file is missing, rather than silently creating a mismatched password. It waits for TCP readiness, then attaches the container to the `kind` network so in-cluster jobs and the runner can reach state as `zdp-tfstate:5432`. The password comes from `od -N16`, because `tr </dev/urandom \| head` gets SIGPIPE under `pipefail`. |
| `test-go.sh` | `unit` runs `go test ./...` in the pinned Go container. `integration` starts throwaway Postgres + Valkey containers on network `zdp-test`, waits for **TCP** readiness (the Postgres image's init phase only listens on a socket), then runs `go test -tags integration ./...` on that network. The containers are removed on exit. |

Further entry points (`up.sh`, `down.sh`, `state-up.sh`, `runner-up.sh`, `gate.sh`, `bump-release.sh`, `restore-test.sh`, demos) are added by later build steps and listed here as they land.

**Conventions:**
- `set -euo pipefail`.
- Source `lib/common.sh`.
- Never hard-code repo or registry names; read `config/platform.env`.
- Never hard-code versions; read `config/versions.env`.

**Label:** RUN-LOCAL.
